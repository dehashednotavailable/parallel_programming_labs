# Лабораторная работа №2 — OpenMP

## Задание

Добавить OpenMP к умножению матриц из [Лабораторной №1](../Lab1/README.md), запустить программу с разным числом потоков и размеров матрицы, сравнить время выполнения.

## Реализация

Код находится в [main.cpp](main.cpp). Внешний цикл по строкам `A` распределяется между OpenMP потоками через `#pragma omp parallel` и `#pragma omp for schedule(static)`. Каждый поток записывает только свои строки `C`, поэтому синхронизация результата не нужна. Порядок вычисления элементов внутри потока совпадает с лабораторной №1.

Число потоков задаётся необязательным последним аргументом, либо переменной окружения `OMP_NUM_THREADS`. Программа сообщает запрошенное и фактически запущенное число потоков. Время включает создание команды и умножение, но исключает чтение входа, выделение массива и запись результата.

## Сборка и запуск

На Mac с Homebrew:

```bash
brew install libomp
make
make example
make check
```

На Linux с GCC:

```bash
make CXX=g++ OMP_CXXFLAGS=-fopenmp OMP_LDFLAGS=-fopenmp
```

Запуск:

```bash
./lab2 data/A.txt data/B.txt data/C.txt 4
python3 ../Lab1/verify.py data/A.txt data/B.txt data/C.txt
```

## Эксперимент

Серия включает размеры `200, 400, 800, 1200, 1600, 2000` и команды `1, 2, 4, 8, 10` потоков. Для каждой пары запускается один прогрев и пять замеров. Python/NumPy сверяет каждый сохранённый результат с `A @ B`. Медианы используются для расчёта ускорения относительно одного потока и эффективности `speedup / threads`.

Воспроизвести серию:

```bash
make experiments
```

Результаты сохраняются в `results/raw.csv`, `results/summary.csv`, `results/environment.json` и графиках `results/speedup.png` / `results/speedup.svg`.

## Вывод

Эксперимент выполнен на Apple M4 (10 логических CPU) с Apple Clang 17 и Homebrew libomp: шесть размеров, пять конфигураций потоков, один прогрев и пять замеров для каждой пары. Все 150 сохранённых результатов прошли сравнение с NumPy при `rtol=1e-9`, `atol=1e-9`.

Для `n=2000` медианное время уменьшилось с `1.0022 с` на одном потоке до `0.2745 с` на десяти; ускорение составило `3.65×`. На четырёх потоках получено `2.69×`. На маленькой матрице запуск дополнительных потоков дороже относительно объёма вычислений, а на больших размерах ускорение растёт, но отстаёт от линейного из-за пропускной способности памяти и накладных расходов параллельного выполнения. Замеры относятся к этому M4 и не экстраполируются на кластер или другой процессор.
