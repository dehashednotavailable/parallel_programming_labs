# Лабораторная работа №3 — MPI

## Задание

Распараллелить умножение квадратных матриц из [Лабораторной №1](../Lab1/README.md) с помощью MPI, проверить размеры `200, 400, 800, 1200, 1600, 2000` и процессы `1, 2, 4, 8`. Итоговая серия по заданию должна быть запущена на суперкомпьютере «Сергей Королёв».

## Реализация

В [main.cpp](main.cpp) матрицы рассылаются процессам, строки результата распределяются блоками с учётом остатка от деления размера на число процессов, а итог собирается на процессе 0. Результаты проверяет Python/NumPy относительно `A @ B`. Таймер MPI охватывает рассылку, вычисление и сбор результата.

## Сборка и локальная проверка

Локально с Open MPI:

```bash
make clean
make
make example
make check
make experiments
```

На «Сергее Королёве» используется Slurm. [Скрипт отправки](submit_on_cluster.sh) собирает программу на login-узле с `intel/mpi5`, а [Slurm-скрипт](run_on_cluster.sbatch) выделяет один узел с восемью задачами и запускает полную серию через `srun`:

```bash
./submit_on_cluster.sh
squeue -u "$USER"
```

Задача использует только стандартную библиотеку Python на вычислительном узле: генерирует детерминированные целочисленные матрицы, выполняет один прогрев и пять замеров для каждой пары размера/числа процессов, а каждый результат побайтно сравнивает с результатом одного процесса. Сжатые эталонные матрицы, CSV и сведения об окружении сохраняются в `results/sergey-korolev`. После завершения скачайте папку результатов и запустите на машине с NumPy независимую проверку и построение графика:

```bash
python3 ../tools/verify_cluster_matrix_results.py --program mpi --results-dir results/sergey-korolev
```

Для локальной серии на Mac или Linux используется Open MPI; для восьми процессов на Mac добавляется `--oversubscribe`.

## Локальные результаты

Чистая локальная серия выполнена на Apple M4 с Open MPI 5.0.11: шесть размеров, 1/2/4/8 процессов, один прогрев и пять замеров для каждой пары. Все 120 сохранённых результатов прошли NumPy-сверку (`rtol=1e-9`, `atol=1e-9`). CSV, среда и график находятся в `results/local`.

Для `n=200` запуск нескольких процессов медленнее одного: затраты на запуск MPI и обмен данными больше самой работы. Лучший результат серии — `2.07×` при `n=800` и четырёх процессах. Для `n=2000` восемь процессов дали `1.68×` (`0.613 с` против `1.030 с` на одном процессе). Скорость масштабирования меняется по размерам, поскольку на локальной машине существенны накладные расходы обмена и запуска; эти числа не представляют производительность кластера.

Локальные тесты подтверждают корректность алгоритма, включая неравное распределение строк. Результаты кластера публикуются отдельно в `results/sergey-korolev`; локальные замеры не выдаются за кластерные.

## Результаты на кластере

Полная серия выполнена 16 октября 2026 года на узле `n248.ssc` под Slurm 20.11.9 с Intel MPI 5.1.3: шесть размеров, 1/2/4/8 процессов, один прогрев и пять замеров на конфигурацию. Все 120 измеренных выходов побайтно совпали с однопроцессным результатом; шесть эталонных матриц отдельно прошли проверку NumPy (`rtol=1e-9`, `atol=1e-9`, максимальная абсолютная ошибка `0`). CSV, среда, сжатые эталоны, проверка и график сохранены в `results/sergey-korolev`.

Для `n=2000` медианное время составило `8.968 с` на одном процессе и `1.889 с` на восьми, ускорение — `4.75×`. Четыре процесса дали `2.715 с` и `3.30×`. Ускорение зависит от размера: на малых матрицах накладные расходы распределения работы заметнее, на больших — масштабирование лучше, но ограничивается последовательной рассылкой данных и сбором результата на корневом процессе.
